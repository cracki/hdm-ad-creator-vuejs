## ۲. موارد باز — ریشه‌یابی، رفع، تست عمومی، تست زنده

### الف) عکس ۱۴ · سهم بودجه‌ی PPC بین سرویس‌ها (بدتر شده — اولویت ۱)

**شواهد QA6:** با انتخاب ۲ سرویس، ۶ سرویس تحلیل شد (۲ انتخابی ۱۹٪+۱۹٪؛ زباله‌ها ۴۸٪؛ Motorcycle انتخاب‌زداده ۱۴٪) + «PPC Ready: 4 of 2».

**فرضیه‌های ریشه (به ترتیب احتمال — هر دو در فاز اجرا با بازتولید زنده تفکیک می‌شوند):**
1. **انتخاب به `context_payload.selected_services` نمی‌رسد/نمی‌ماند:** فرانت هنگام Create می‌فرستد (CampaignCreateView.vue:73) و سریالایزر فیلد را دارد (serializers.py:91)؛ ولی اگر کاربر بعد از Create سرویس را در صفحه‌ی کمپین کم/زیاد کند، مکانیزم ذخیره‌ی آن صفحه (احتمالاً سرویس‌های managed برند از طریق `sync_campaign_services`) شاید `context_payload` را بازنویسی نمی‌کند و مقدار Create باقی می‌ماند یا برعکس. باید مسیر FE بعد از Create ردیابی و بازتولید شود.
2. **fallback به لیست برند با سقف ۶** (ppc_viability.py: `_filter_selected_services` → اگر خالی، brand services) — عامل آمدن ۶ مورد.
3. **فیلتر زباله دو رشته را رد نکرده:** «0% interest installment plan» (باید `\b0%`/`\binstallment` بگیردش — چرا نگرفته؟ احتمال: این رشته از مسیر `services_bpc_scores` قدیمی/کش‌شده می‌آید نه از فیلتر امروز) و «Special discounts for AL SAADA…» (`\bdiscount\b` با «discounts» جمع، مچ نمی‌شود — **باگ الگو: نیاز به `discounts?`**).
4. **«PPC Ready: 4 of 2»** شمارنده‌ی FE: صورت = کارت‌های primary (تعداد تحلیل‌شده)، مخرج = انتخابی‌ها.

**رفع:** (الف) اتصال قطعی انتخاب→context_payload در هر دو مسیر Create و ویرایش بعدی (تست یکپارچه FE+BE)؛ (ب) الگوها: `\bdiscounts?\b`، `\bfixed[-\s]?price\b`، `\bbuy\s+\d+\s+get\b`؛ (ج) PPC تحلیلاً فقط انتخابی‌ها (اگر انتخاب ≤ ۶: همان‌ها، بدون fallback)؛ (د) شمارنده‌ی «PPC Ready» = تعداد تحلیل‌شده در هر دو صورت و مخرج.

**تست عمومی (نه مثال‌محور):** کورپوس ۴۰+ رشته‌ی تولیدی تخفیف/قسط/آمار/شعار (ترکیب تصادفی اعداد/کلمات) + ۳۰ سرویس واقعی از ۵ صنعت — همه با property-based assertion. تست یکپارچه: Create با ۲ انتخاب → context_payload → run PPC → دقیقاً همان ۲ سرویس، جمع ۱۰۰.

**تست زنده + اسکرین‌شات:** ساخت کمپین جدید با ۲ سرویس انتخابی (برند EDI جدید یا موجود) → اجرای PPC → ① اسکرین‌شات صفحه‌ی PPC (بج‌های سهم فقط ۲ سرویس، جمع ۱۰۰٪) ② کارت کمپین بدون «4 of 2» ③ JSON فیلد `selected_services` از API به‌عنوان شاهد میانی.

### ب) تازه ۲ · Positioning فارسی (کش نتایج قدیمی)

**شواهد QA6:** تحلیل جدید ۱۷ اکتبر دقیقاً همان جمله‌ی فارسی قبلی را برگرداند — کلمه‌به‌کلمه. پرامپت اصلاح‌شده هرگز اجرا نشده.

**فرضیه:** بخش insights/رقبا در تحلیل مجدد **بازتولید نمی‌شود** و نتیجه‌ی قبلی (identity-level کش/ردیف مشترک، مثل همان الگوی copy-on-write که در سرویس‌ها دیدیم) برگردانده می‌شود. مسیر: `analyze_competitors` / `generate_competitive_insights` و جایی که `positioning_recommendations` خوانده/ذخیره می‌شود (brand/models یا full_analysis).

**رفع:** (الف) در هر Analyze جدید، Positioning/Insights حتماً با پرامپت جدید بازتولید شود (حذف شرط «اگر رقیب هست، insights را نگه دار») یا دست‌کم insights جدا از رقبا re-generate شود؛ (ب) مهاجرت داده‌ی قدیمی: رشته‌ی فارسی موجود در برندهای قبلی با re-analyze جایگزین می‌شود (همان چیزی که کارفرما اجرا کرد و باید جواب بدهد).

**تست زنده + اسکرین‌شات:** برند EDI جدید (یا Re-Analyze با force) → تب Competitors → ① اسکرین‌شات Positioning به انگلیسی ② تاریخ/ساعت run جدید در تصویر (بج نسخه + زمان تحلیل) تا «نتایج قدیمی» رد شود.

### ج) عکس ۲ · زباله‌ی نوع ۳ («Buy 1 get 1…»، «Fixed price … for …»)

**رفع:** الگوهای عام: `\bbuy\s+\d+\s+(get|free)\b`، `\bfixed[-\s]?price\b`، `\bmartyrs?\b`/`\bfamilies\s+of\b` (موارد ملی/خیری)، و قاعده‌ی عمومی‌تر: هر رشته‌ی >۶ کلمه با فعل تبلیغاتی (get/save/enjoy/only) در context سرویس drop — به‌علاوه همان رشته‌ها از فیلد `services` تحلیل هم (مسیر persist از قبل فیلتر می‌کند؛ الگوی جدید هر دو را می‌پوشاند).

**تست عمومی:** همون کورپوس تولیدی بخش (الف) + این دو خانواده.

**تست زنده + اسکرین‌شات:** اسکن edi-uae.com در فرم برند جدید → ① پنل Detected services بدون این دو رشته ② Edit برند → لیست Scanned تمیز ③ بعد از تحلیل، Services در Overview فقط دوره‌های واقعی.

### د) تازه ۴ · فیلدهای Country/City خالی در فرم + Product description

**رفع (کاملاً FE):** فرم Segmentation هنگام لود، Country/City را از همان لوکیشن برند که بک‌اند استفاده می‌کند پیش‌پر کند (split «Dubai, UAE» → City=Dubai/Country=UAE؛ قابل ویرایش) و Product description را از سرویس‌های **انتخابی کمپین** بسازد نه دوره‌های تحلیل برند.

**تست زنده + اسکرین‌شات:** کمپین جدید → صفحه‌ی Segmentation قبل از Run: ① فیلدهای Country/City پر ② Product description شامل دو سرویس انتخابی.

### هـ) تازه ۵ · چیپ‌های خام + Completed=۹۰٪ + Review=۱۰۰٪ قبل از Complete

**رفع:** (الف) FE چیپ‌های `missing` خام را به برچسب انسانی ترجمه کند (یا فقط پیام detail را نشان دهد)؛ (ب) کمپین‌های `status=COMPLETED` همیشه ۱۰۰٪ نمایش داده شوند (فلگ جامانده علت ۹۰٪ است — یا فلگ درست ست شود یا نمایش override)؛ (ج) تصمیم محصول پیشنهادی: Review قبل از زدن Complete حداکثر «۹۹٪ · آماده‌ی تکمیل» نشان دهد نه 100% (یا دقیقاً همان ۱۰۰٪ ولی با برچسب «Ready to complete» — یکی انتخاب و در گزارش ذکر می‌شود؛ پیش‌فرض: برچسب «Ready»، نه تغییر عدد). (د) مخرج متغیر (۸/۹/۱۰ بسته به پلتفرم‌های انتخابی) طبق توضیح خود کارفرما «طراحی» است — یکدست‌سازی نمایشی: نمایش «M/T steps» با T واقعی همان کمپین در همه‌ی کارت‌ها (بعد از رفع ب، اعداد همیشه سازگار می‌شوند).

**تست زنده + اسکرین‌شات:** ① صفحه‌ی Review با پیام انسانی بدون چیپ خام ② لیست کمپین‌ها: همه‌ی Completed=۱۰۰٪، بقیه M/T سازگار ③ Review بعد از آگهی+تصویر با برچسب Ready.

### و) جدید ۶ · سرویس‌های Analysis در پیش‌پر Intelligence و پیشنهاد فرم کمپین

**شواهد QA6:** Industry/Location درست؛ تخفیف‌ها حذف؛ ولی فقط سرویس Manual آمد و دوره‌های Analysis (Gold/Gold Excellence/Platinum) نیامدند — در فرم کمپین هم فقط Car Driving + Motorcycle.

**فرضیه:** فیلد `brand.services` در آبجکت برندِ FE فقط سرویس‌های managed را دارد؛ سرویس‌های `brand_analysis` از endpoint جدا (`GET /brands/{uuid}/services/` با source) می‌آیند و prefill فعلی فقط `brand.services` را می‌خواند؛ در فرم کمپین هم لیست پیشنهاد از همان مسیر ناقص تغذیه می‌شود.

**رفع:** prefill هر دو صفحه از endpoint کامل services با فیلتر source ∈ {manual, brand_analysis} (سقف ۸ برای Intelligence؛ فرم کمپین بدون سقف Intelligence) — بعد از رفع (ج) این لیست ذاتاً تمیز هم هست.

**تست زنده + اسکرین‌شات:** ① فرم Intelligence با برند EDI: Brand services شامل دوره‌های Analysis + Industry/Location پر ② فرم ساخت کمپین: پیشنهادها شامل هر دو گروه.

## ۳. روش اجرای تست زنده (پاسخ مستقیم به درخواست کارفرما)

برای **هر مورد**، بعد از رفع و دیپلوی:

1. **بازتولید مستقل:** با حساب تست، برند جدید (EDI تازه یا سایت ساده دیگر) + کمپین جدید از صفر تا Complete — دقیقاً همان مسیر کارفرما، بدون میان‌بر API (API فقط برای شاهد میانی).
2. **اسکرین‌شات‌ها** با URL نوار آدرس + بج نسخه‌ی Sidebar در قاب (اقدام به‌جای ادعا — بج نشان می‌دهد کدام بیلد تست شده) در `docs/mom/evidence/qa6/<item>/` و **embed مستقیم در گزارش رفع**.
3. **شاهد میانی JSON** برای هر مورد (مثلاً `context_payload.selected_services` برای عکس ۱۴) تا اگر UI درست بود ولی داده غلط، معلوم شود.
4. **رگرسیون عمومی:** کورپوس قاعده‌محور (نه فقط مثال‌های گزارش) در تست‌های خودکار — پاسخ به «مثال‌ها بسته شده‌اند، نه نوع مشکل».
